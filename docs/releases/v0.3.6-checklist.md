# PriorityGear v0.3.6 Release Checklist

## Scope Summary

- Process-name filtering in the process grid.
- Manual `3s snapshot` action for one-shot process resource measurement.
- CPU snapshot metrics from process CPU-time deltas.
- Disk I/O snapshot metrics from process I/O counter deltas.
- GPU shown as an explicit unsupported/unavailable state unless verified PID attribution is available.
- Metric sorting and filtering for CPU, GPU, and Disk I/O snapshot data.
- Priority selectors ordered high to low.
- Active priority defaults to `Same as normal`.
- Core Reserve rule setting for physical-core affinity reservation.
- `PriorityGear.Cli core-topology` diagnostic for physical-core topology and allowed/reserved masks.
- Installed System Mode validation for `vmmemWSL.exe`.
- Validation Safety policy for live user infrastructure.

## Known Limitations

- GPU process attribution remains unsupported unless a verified PID-attributed source is added later.
- Multiple processor groups are rejected by the current Core Reserve affinity path.
- Protected or elevated processes may require System Mode.
- Deleting a rule does not necessarily restore priority or affinity already applied to a running process.
- Validation must not stop or restart WSL, Docker, containers, databases, VS Code remote sessions, or other user workloads as routine cleanup.

### winget validation result

- Pull request: `microsoft/winget-pkgs#381611`.
- Validation result: `Validation-Unattended-Failed`.
- Direct failure: the validation VM downloaded the ZIP, verified the hash, extracted `PriorityGear.Setup.exe`, started `PriorityGear.Setup.exe --install --silent`, and then `PriorityGear.Setup.exe` displayed the .NET Desktop Runtime requirement dialog.
- Cause: the `v0.3.6` release artifact was framework-dependent. `scripts/package-release.ps1` published the setup, GUI app, CLI, and service with `--self-contained false`.
- Decision: do not continue the `v0.3.6` winget submission as-is and do not mutate the published `v0.3.6` tag or release assets.
- Next product release target: a self-contained installer artifact, likely `v0.3.7`, where the setup executable and installed payload can run on a clean Windows validation machine without a separately installed .NET Desktop Runtime.
- No live install/uninstall validation was run on the user workstation during this failure analysis.
